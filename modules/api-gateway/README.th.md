# เกตเวย์ API สำหรับแอปภายนอก (api-gateway)

ให้แอปการเรียนภายนอกอ่านข้อมูลโรงเรียนอย่างปลอดภัย แทนวิธีเดิมที่ใช้คีย์ร่วมและส่ง SQL SELECT ตรงเข้าฐานข้อมูล

## สิ่งที่โมดูลให้

| ส่วน | รายละเอียด |
| --- | --- |
| ขอโทเคน | `POST /api/v1/token` หรือ `POST /oauth/token` แบบ OAuth2 `client_credentials` ส่ง `client_id` กับ `client_secret` ด้วย HTTP Basic หรือในเนื้อคำขอ ได้ bearer อายุ 1 ชั่วโมง |
| ข้อมูล | `GET /api/v1/students`, `/classrooms`, `/teachers`, `/courses`, `/attendance/summary` (แบ่งหน้าด้วย `cursor`, `limit` สูงสุด 500) |
| นักเรียนเข้าสู่ระบบ | `GET /oauth/authorize` (authorization code + PKCE S256) แล้วแลก code ที่ `POST /oauth/token` ได้โทเคนอ่าน `GET /api/v1/me` |
| หน้าจัดการ | เมนูงานโรงเรียน `#api` (ผู้ดูแลระบบ) สร้างไคลเอนต์ แสดง secret ครั้งเดียว เลือก scope ออก secret ใหม่ เพิกถอน ดูการใช้งาน 7 วัน |
| PIN นักเรียน | เมนู `#student-pins` ผู้ดูแล/ผู้อำนวยการออกได้ทุกห้อง ครูประจำชั้นออกและรีเซ็ตได้เฉพาะห้องตัวเอง พิมพ์เป็นใบ PIN |

## Scope และข้อมูลที่ออกไป

ทุก field ถูกกำหนดในคลาส `Presenter` ที่เดียว เพิ่มคอลัมน์ในฐานข้อมูลไม่ทำให้ข้อมูลหลุดออกไปเอง

| scope | ได้อะไร |
| --- | --- |
| `students:read:basic` | id, code, display_name, classroom, status |
| `students:read:contact` | เพิ่มรายการ `contact` ของผู้ปกครอง (ชื่อ ความสัมพันธ์ อีเมล) เฉพาะที่ผู้ปกครองอนุญาตให้แชร์กับแอป ตอนนี้ทะเบียนยังไม่มีสถานะยินยอม (`reg_student_guardians.share_contact_with_apps`) จึงได้รายการว่าง |
| `classrooms:read` | id, name, grade_level, ครูประจำชั้น (ชื่อ) |
| `teachers:read:basic` | id, display_name, subject |
| `courses:read` | รายวิชาที่เปิดสอนตามภาคเรียน (ต้องมีโมดูลวัดผล ไม่มีจะตอบ 404 `not_available`) |
| `attendance:read:summary` | จำนวนการมาเรียนรวมต่อห้องและสถานะ ไม่ระบุตัวนักเรียน |
| `sso:student` | ให้นักเรียนเข้าสู่ระบบแอปนี้ด้วยรหัสนักเรียนและ PIN |

ไม่มี scope ใดให้วันเกิด เลขประจำตัวประชาชน/หนังสือเดินทาง/เลข G เอกสาร ข้อมูลสุขภาพ ที่อยู่ เบอร์โทร หรือ PIN

## ความปลอดภัย

- secret และโทเคนเก็บเฉพาะค่าแฮช (secret ด้วย bcrypt, โทเคนด้วย SHA-256) แสดงครั้งเดียวตอนสร้างหรือออกใหม่
- ออก secret ใหม่หรือเพิกถอนไคลเอนต์ โทเคนที่ออกไปแล้วถูกเพิกถอนทันที ลด scope ของไคลเอนต์มีผลกับโทเคนเดิมทันที
- rate limit ต่อไคลเอนต์ (ค่าเริ่มต้น 120 ครั้ง/นาที) เกินแล้วได้ 429 พร้อม `Retry-After` และมี limit แยกสำหรับขอโทเคนและรหัส secret ผิด
- IP allowlist (IP เดี่ยวหรือ CIDR ทั้ง v4/v6) ตรวจทั้งตอนขอโทเคนและทุกคำขอ
- ทุกคำขอบันทึกใน `api_request_log` (เส้นทาง สถานะ เวลา) ไม่บันทึก query string หรือโทเคน
- เส้นทางเครื่อง-ต่อ-เครื่อง (`/api/v1/*`, `/oauth/token`) ไม่ใช้ session หรือ CSRF ส่วนหน้า `/oauth/authorize` เป็นฟอร์มเบราว์เซอร์จึงยังเปิด CSRF
- นักเรียนเข้าสู่ระบบด้วยรหัสนักเรียนกับ PIN 6 หลักเท่านั้น ไม่ใช้วันเกิด ใส่ PIN ผิด 5 ครั้งล็อก 30 นาที (นับก่อนตรวจ PIN จึงยิงขนานไม่ได้เกิน 5 ครั้ง) ครูประจำชั้นรีเซ็ตเพื่อปลดล็อก ข้อความผิดพลาดเหมือนกันทุกกรณี และจำกัดต่อ IP 20 ครั้ง/5 นาที
- code ใช้ได้ครั้งเดียวและมีอายุ 2 นาที ใช้ซ้ำจะถูกปฏิเสธและเพิกถอนโทเคนที่ code นั้นเคยออก ตรวจ `redirect_uri` ตรงตัวและ `code_verifier` (S256)
- PIN เก็บเป็น bcrypt ของ HMAC (ผูก `APP_KEY`) ไม่ลงในบันทึกตรวจสอบ ใบ PIN พิมพ์ได้ครั้งเดียวจากหน้าที่ออก PIN

## ตั้งเวลาล้างข้อมูลเก่า

คำสั่ง `php artisan saan:api-prune` ลบ log เก่ากว่า 30 วัน โทเคนที่หมดอายุหรือถูกเพิกถอนเกิน 7 วัน และ SSO code ที่หมดอายุเกิน 1 วัน (`--days=N` ปรับอายุ log, `--dry-run` ดูก่อน) โมดูลไม่ตั้งเวลาเอง ให้ผู้ดูแลเลือกอย่างใดอย่างหนึ่ง

```php
// routes/console.php
Schedule::command('saan:api-prune')->dailyAt('03:30')->withoutOverlapping();
```

หรือใส่ใน cron ของเซิร์ฟเวอร์: `30 3 * * * php /path/to/school-app/artisan saan:api-prune`

## ย้ายจากระบบเดิม (login-api และ SQL proxy)

ระบบเดิมของหลายโรงเรียนให้แอปภายนอกส่งคีย์ร่วมแล้วรัน SQL SELECT ตรง และล็อกอินนักเรียนด้วยรหัสนักเรียนกับวันเกิด วิธีนี้เปิดให้อ่านได้ทุกตารางและวันเกิดไม่ใช่ความลับ ขั้นตอนย้ายแนะนำดังนี้

1. เขียนรายการ SQL ที่แอปภายนอกเรียกจริงจาก log ของ proxy เดิม แล้วจับคู่กับ endpoint ใหม่: รายชื่อนักเรียนใช้ `/api/v1/students?classroom=`, ห้องเรียนใช้ `/classrooms`, ครูใช้ `/teachers`, รายวิชาใช้ `/courses`, สถิติมาเรียนใช้ `/attendance/summary` ข้อมูลที่ไม่มี endpoint รองรับ (เช่นวันเกิด เลขประชาชน) ตั้งใจไม่ให้ ให้ขอเพิ่ม scope ที่เหมาะสมกับทีมพัฒนา แทนการเปิดตาราง
2. สร้างไคลเอนต์ในหน้า `#api` ให้แอปภายนอกหนึ่งตัว เลือกเฉพาะ scope ที่จำเป็น ใส่ IP ของเซิร์ฟเวอร์แอปใน allowlist ส่ง `client_id` และ secret ให้ผู้ดูแลแอปทางช่องทางส่วนตัว
3. ให้แอปขอโทเคนแล้วเรียก API ใหม่คู่ขนานกับระบบเดิมสักสัปดาห์ เทียบผลและดูกราฟการใช้งาน 7 วัน ปรับ `rate_per_minute` ให้เหมาะกับปริมาณจริง (เดิมราว 21,000 ครั้งใน 2 ชั่วโมง ควรให้แอปแคชรายชื่อ แล้วใช้ `cursor` แทนการถามซ้ำ)
4. เปลี่ยนการเข้าสู่ระบบนักเรียนเป็น authorization code + PKCE: ลงทะเบียน Redirect URI (https) ให้ scope `sso:student` ให้แอปส่งนักเรียนมาที่ `/oauth/authorize` แล้วแลก code ที่ `/oauth/token` ก่อนนี้ครูประจำชั้นออก PIN ให้ทั้งห้องที่เมนู `#student-pins` และพิมพ์ใบแจกนักเรียน
5. ปิดวิธีเดิมเมื่อไม่มีการเรียกค้างแล้ว: ลบคีย์ร่วม ปิดหน้า SQL proxy และ login-api เดิม เปลี่ยนรหัสผ่านบัญชีฐานข้อมูลที่ proxy เคยใช้ แล้วสังเกต `api_request_log` ว่าไม่มีคำขอ 401 จากแอปเดิมค้างอยู่

### ตัวอย่างเรียกจากเซิร์ฟเวอร์แอป

```
POST /api/v1/token
Authorization: Basic base64(client_id:client_secret)
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials

GET /api/v1/students?classroom=3&limit=200
Authorization: Bearer saan_...
```

## ตาราง

`api_clients`, `api_tokens`, `api_request_log`, `api_sso_codes`, `api_student_pins` ปิดโมดูลแล้วข้อมูลยังอยู่ (`keep-data`)

## ข้อจำกัดที่ทราบ

- รองรับเฉพาะนักเรียนใน SSO (ตารางรองรับ `user_kind = staff` แล้ว แต่ยังไม่เปิดใช้)
- ไคลเอนต์ต้องมี secret (confidential client) ยังไม่มี public client สำหรับแอปในเครื่องที่เก็บ secret ไม่ได้ และยังไม่มี refresh token
- `local_only` ของระบบ (ค่าเริ่มต้นเปิด) จะรับเฉพาะ localhost จึงต้องปิดเมื่อติดตั้งจริงเพื่อให้แอปภายนอกเข้าถึงได้
- IP allowlist ใช้ `$request->ip()` หากอยู่หลัง reverse proxy ต้องตั้ง trusted proxy ให้ถูกต้อง
